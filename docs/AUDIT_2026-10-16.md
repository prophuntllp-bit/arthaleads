# ArthaLeads full code and app audit, 16 Oct 2026

Seven read-only reviews (security and tenant isolation, scale and performance,
correctness and reliability, dead and stale code, web frontend, infrastructure,
mobile app), each finding backed by file:line. The most serious findings were then
re-checked by hand; "Verified" means reproduced or confirmed by reading the code
path end to end. Nothing was changed during the audit.

Baseline: 613 automated checks pass (one Windows-only exit crash after the last
test file, harmless on Linux). The web app builds cleanly. No secrets in git.

## P0: fix now (live risk today)

| # | Problem | Where | Status |
|---|---|---|---|
| P0-1 | **One unauthenticated request crashes the whole API** (`/api/media/%25E0`: decodeURIComponent throws outside try, and `unhandledRejection` calls `process.exit(1)`). Repeating it keeps every company offline. | `routes/mediaRoutes.js:36`, `server.js:14-17` | Verified (reproduced locally) |
| P0-2 | **NoSQL injection on public lead-intake tokens**: `{"token":{"$regex":"^a"}}` is passed to Mongo, so tokens can be guessed one character at a time (401 vs 200), then fake leads, phone-number probing, overwriting site settings. | P0-3 | **Same injection on the AiSensy WhatsApp webhook**: `{"apiKey":{"$gt":""}}` matches any org with WhatsApp, so forged chats, leads, and AI-bot replies sent from that org's number on its credits. | `routes/whatsappRoutes.js:2528-2530` | Verified (pattern reproduced) |
| P0-4 | "Generate template with AI" broken since 11 Sep: `generateWhatsAppTemplate` is not exported. | `utils/openai.js:112, 1106` | Verified |

Fix shape: a global guard that rejects any `$`-operator object where a string is
expected (Mongoose `sanitizeFilter` or a small middleware) plus `String(token)` at
each site; try/catch on media decode; log + report unhandled rejections to Sentry
instead of exiting; add the export.

## P1: before onboarding large companies

### Security
- **Managers can move a project into another company or delete another company's files**: `PUT /projects/:id` passes `req.body` unvalidated to `findOneAndUpdate` (`services/projectService.js:125-133`), so `orgId`, `qrToken`, `images` can be set. Verified.
- **Stored XSS on the API domain via uploads**: attendance selfie / project images / logo accept any data-URI type (`utils/storage.js:76`, `attendanceController.js:120`), served as-is from `/api/media`. Likely (needs runtime check of B2 content type).
- **Google sign-in accepts tokens issued to any Google app** (no audience check): `services/authService.js:253-258`. Verified.
- **One company can capture another company's Facebook leads** by creating an automation with the other's page ID and no form ID: `webhookRoutes.js:217-231`, `validations/schemas.js:76-94`. Verified.
- WhatsApp webhooks for AiSensy/Wati/Interakt are unsigned; Meta signature only enforced if `WA_WEBHOOK_ENFORCE=true` (check production). EnableX webhooks unsigned; forged events can make the server fetch an attacker URL with the org's EnableX credentials.
- Agent visibility gaps: old helpbot context (`helpRoutes.js:102`, `copilotContext.js`), `POST /whatsapp/conversations/start`, `/leads/:id/retry-facebook`, `/draft-message` routes.
- Org admin may be able to reset the super admin's password if the super admin account still has an orgId (`authService.updateUser`). Needs runtime check.
- OAuth popup `postMessage` handlers don't check origin (`frontend Automation.jsx:183, 1255`); website `site_url` rendered as a link without scheme check (`ConnectionCard.jsx:169`).
- Unescaped user input in `$regex` (`followupService.js:24`, `enablexRoutes.js:560`, `helpRoutes.js:102`).
- Dependencies: backend 1 critical / 6 high (axios, joi reachable), frontend 4 high (xlsx on uploaded sheets).

### Money (WhatsApp credits)
- **A credit hold can be released twice** when Meta's `sent` and `delivered` statuses race, so a company can send past its balance (`creditService.js:249-277`, `whatsappRoutes.js:351-366`). Verified by reading.
- Holds that never settle are never released (crash mid-campaign, status webhook before the message row exists, lost webhooks). No sweeper.
- `settle()` can drive the balance negative; free-tier flag taken from a pre-reserve quote.

### Leads
- Facebook lead webhook has no dedupe on `metaLeadId` and does all work before replying, so Meta retries create duplicates (`webhookRoutes.js:417-779`).
- Google Ads webhook returns 200 on server errors, so failed leads are lost (`webhookRoutes.js:1704-1709`).
- Phone numbers normalised five different ways across lead paths: the same person becomes two leads.
- Deleted users keep receiving leads through routing rules (`routingRules.js:23`, `authService.deleteUser`).

### Data safety and operations
- **Nightly backup covers 8 of 37 collections** (no WhatsApp, payments, invoices, tasks, integrations), loads everything into memory, emails it unencrypted, and will exceed email size limits as data grows (`utils/backup.js`). Verified.
- **Every backend release deploys twice** (Railway GitHub integration and `railway up` in `deploy-backend.yml` race; first is REMOVED). The workflow reports success before Railway builds. Verified.
- No tests or build run before going live; staging and main have diverged (cherry-picks), so live is never the exact commit tested.
- Campaign sending runs inside the HTTP request; a restart leaves it stuck "sending" with credits held.
- Cron and webhook failures only go to logs; nothing alerts. `/health` doesn't check the database. No uptime monitor.
- Required environment variables not checked at boot; staging falls back to production URLs (`APP_URL`).

### Scale (200k leads, 1M messages)
- Every-minute reminder scans all project leads (no usable index) (`scheduler.js:114`). Verified.
- Leads page poll: ~20 DB operations every 15 s per tab including an unindexed project-lead phone lookup (`projectCopies.js:28`). Verified (index missing).
- `/leads/hot` loads every open lead with history before taking 4 (`leadRoutes.js:36`). Verified.
- The WhatsApp page (Inbox.jsx) polls every 3 to 4 s with a write each time; Pipeline loads 1,800 full documents every 30 s; no pause when the tab is hidden.
- Missing indexes: ProjectLead `{orgId, phone}`, `{followUp}`, `{followUp2}`; WaConversation `{orgId, leadId}`, `{orgId, assignedTo, lastMessageAt}`; WaMessage `{orgId, direction, timestamp}`, `{conversationId, direction, timestamp}`; PushSubscription `{userId}`; Task `{status, dueDate}`; Attendance `{orgId, date}`.
- Follow-ups "past" aggregation and dashboard analytics `$facet` will hit Mongo memory limits.
- Lead `activities`, `notes`, `voiceCalls` arrays grow forever and are returned in list views.
- No response compression. Single-instance assumptions (in-memory queues, timers, caches, rate limits, crons without locks).

### Web app bugs
- Wrong password on super-admin login spins forever (`services/api.js:85` regex misses `admin-login`). Verified.
- Editing a task shows the time 5h30 early and re-saving moves it (`pages/Tasks.jsx:215`). Verified.
- Every 401 becomes a never-ending promise (spinners that never stop).
- Editing a lead resets its follow-up time (`LeadForm.jsx:89`); "today" computed in UTC in seven places.
- Dump Leads stops at 500.

## Mobile app (for the APK session; mobile/ not changed by this audit)

- **The 7-day sign-out fix is not in any released APK yet** (landed after build 39). Ship build 40.
- After an automatic sign-out the phone keeps receiving the old user's lead notifications; a different user signing in gets none (`auth_state.dart:28-34`, `push_service.dart:127`).
- Production server address hard-coded in three screens (`automation_screen.dart:23`, `automation_form.dart:30`, `telephony_integration_screen.dart:216`); one points to a webhook path that doesn't exist.
- Sign-in token sent in a URL for Facebook connect (`automation_screen.dart:836`; server side `automationController.js:463`).
- Dates shown in the phone's time zone instead of IST in ~38 places; date pickers save in phone time.
- Tasks list unpaged; Dump list cut at 1,000; polling continues in the background; ~36 setState-after-await without mounted check; failed loads look like empty lists.
- CI runs only on main (staging pushes not analysed); release APK silently falls back to debug signing without key.properties; handoff doc versions stale.
- All 292 mobile API calls match real server routes.

## Suggested order

1. P0 fixes (today, staging then live).
2. Security P1 (project mass assignment, uploads, Google audience, Facebook capture, webhook signatures, agent gaps).
3. Money: credit hold claim-before-settle and a stale-hold sweeper.
4. Backups (full mongodump to object storage, encrypted, alerting) and single deploy path with a test gate.
5. Indexes and polling changes (biggest scale win for least risk).
6. Lead integrity (Facebook dedupe, Google 5xx, phone key, routing to inactive users).
7. Web app bugs, then P2 tidy-up.
